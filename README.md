# Glam By KT

Create the initial frontend scaffold for a premium bilingual website called Glam By KT, the personal brand of a Stockholm-based hairdresser and makeup artist.

For this first step, focus only on establishing:

The overall visual direction.

A reusable design system.

The basic homepage structure.

Responsive desktop and mobile layouts.

A maintainable component structure.

The visual direction should communicate sophisticated luxury through generous whitespace, restrained styling, strong typography, high-quality editorial presentation, and a calm neutral colour palette. It should feel premium and modern rather than decorative, flashy, or template-like.

Create an initial homepage with these sections:

Header with the Glam By KT brand, navigation, language control, and a prominent booking action.

Hero introducing Kela and emphasizing professional hair artistry.

Specialist-services section emphasizing bleaching, highlights, toning, colouring, cutting, and makeup.

About preview introducing Kela’s experience and expertise.

Selected-work or gallery placeholder.

Final booking call to action.

Minimal footer with contact, Instagram, language, and booking links.

The attached photographs are approved client assets. Use them selectively to support the editorial, premium visual direction. Do not alter the represented work, and do not use every image merely because it was supplied.

Important constraints:

The website must support Swedish and English.

All appointment booking happens externally through BokaDirekt.

Booking links must open in a new tab.

Do not add a database, authentication, CMS, backend, Supabase, or Lovable Cloud functionality.

Do not invent prices, testimonials, awards, contact details, addresses, booking URLs, service details, or business claims.

Use clearly identifiable placeholders where approved assets or information are missing.

Do not generate a replacement logo. Reserve an appropriate location for the existing Glam By KT logo.

Do not use generic stock imagery as though it belongs to the client. Use neutral visual placeholders for now.

Keep the implementation focused on the frontend scaffold and homepage. Do not build additional pages yet.

Use semantic HTML, accessible controls, visible focus states, sensible heading hierarchy, and responsive behaviour.

Keep the generated code clean, reusable, and straightforward enough for continued local development.

Before implementing, briefly describe the proposed visual concept and page structure. Then implement the scaffold.
